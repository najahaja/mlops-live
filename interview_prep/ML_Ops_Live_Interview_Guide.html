  • Interview Response: "As we hardened the system—adding delayed ground-truth tracking, asset sanitization, and automated UI regression testing—we expanded test coverage from 54 to 79 tests."

    • Discrepancy 2: Negative Drift Control on 4.2-Day Validation Slice

  • What happened: Initially, comparing Jan Train (23 days) to Jan Val (4.2 days) showed raw PSI of 2.03 on pickup_day_of_week. This looked like severe drift, but was actually an artifact of an incomplete calendar window (the validation slice spanned Tuesday–Saturday and had zero Sunday/Monday trips).
  • How it was fixed: In src/mlops_live/monitoring/drift.py, check_weekday_coverage() was implemented. It checks if $\ge 7$ elapsed days are present and all weekdays have $\ge 5$ observations. If not, it sets evaluation_status = "insufficient_data" and prevents false retraining.
  • Interview Response: "This was a critical real-world bug we discovered. Short time windows produce artificial categorical drift. Implementing calendar-coverage validation prevented our automated pipeline from triggering false retraining."

    • Discrepancy 3: Controlled Drift Experiment vs. Live Traffic Drift

  • What happened: Real February 2024 data showed natural stability (zero drift, PSI < 0.02). To prove that retraining, champion/challenger gating, and rollback actually work when drift occurs, we constructed a controlled sandbox experiment (reports/generated/controlled_drift_retraining_report.json) by filtering for long-haul trips (> 3.5 miles).
  • Interview Response: "I clearly distinguish natural multi-month stability from our controlled sandbox experiment. In real February data, there was no drift. So to validate that our drift gates and automated rollback work under stress, we engineered a synthetic regime shift in an isolated sandbox."

    • 3. Known Architectural Limitations & Trade-Offs

    Be honest about these when asked "What is the weakest part of your architecture?": 1. SQLite Concurrency Bottleneck (Database Lock):
  • SQLite uses file-level locking for writes. Under high write concurrency (multiple parallel /predict or /feedback requests), SQLite will throw database is locked (OperationalError).
  • Fix in production: Migrate to connection-pooled PostgreSQL or ingest logs asynchronously via a message queue (Kafka / RabbitMQ / AWS SQS).
    • 2. In-Memory Target Encoding on Location IDs:
  • In src/mlops_live/models/train.py, TargetEncoder is used for PULocationID and DOLocationID with 5-fold cross-validation. If an entirely unseen taxi zone ID arrives at inference time, it falls back to the global target mean.
  • Fix in production: Maintain an explicit unknown-category smoothing strategy or pre-computed zone embeddings.
    • 3. In-Process Prediction Logging (Latency Impact):
  • In src/mlops_live/serving/app.py, log_prediction_record() runs synchronously inside predict() before returning the response. This adds disk I/O to the client's request-response latency.
  • Fix in production: Use FastAPI BackgroundTasks or publish the prediction event to a background Redis queue/worker so inference latency is decoupled from database logging.
    • 4. Single-Node MLflow Registry:
  • MLflow is running on a local SQLite database (sqlite:///mlflow.db) with artifacts on the local filesystem (mlruns/). If the server disk crashes, model lineage is lost.
  • Fix in production: Deploy a remote MLflow Tracking Server backed by Amazon RDS (PostgreSQL) and Amazon S3 or Google Cloud Storage for immutable model artifact storage.
    • 5. No Concept Drift Detection with Delayed Labels:
  • PSI and KS tests detect data drift (covariate shift in inputs and output distributions), but cannot detect concept drift (where $P(Y|X)$ changes but $P(X)$ looks identical) until actual labels arrive via /feedback.

    • Q15: How does Ridge Regression work mathematically, and why did you use it?

  • Difficulty: Intermediate
  • Model Answer:
    • "Ridge regression is linear regression with $L_2$ Tikhonov regularization. Instead of minimizing just the sum of squared residuals, it minimizes: $$\mathcal{L}_{\text{Ridge}} = \sum_{i=1}^{n} (y_i - \hat{y}_i)^2 + \alpha \sum_{j=1}^{p} w_j^2$$ The penalty on the squared magnitude of coefficients shrinks the weights toward zero without setting them strictly to zero (unlike $L_1$ Lasso). I chose Ridge because one-hot encoding PULocationID and DOLocationID creates over 500 sparse dummy columns. In standard Ordinary Least Squares, collinearity between adjacent zones or low-frequency pickup zones causes high coefficient variance and overfitting. The $L_2$ penalty stabilizes the matrix inversion $(X^T X + \alpha I)^{-1} X^T y$ and prevents explosive weights."
  • Technical Depth:
    • $\alpha = 1.0$ controls the bias-variance trade-off. Features are scaled via StandardScaler(with_mean=False) on sparse matrices to ensure the penalty applies equally across all features regardless of scale.

    • Q17: Explain MAE, RMSE, and $R^2$. Why is MAE your primary gate metric?

  • Difficulty: Intermediate
  • Model Answer:
    • "Let $y_i$ be ground truth and $\hat{y}_i$ be prediction for $n$ samples:
  • Mean Absolute Error (MAE): $\frac{1}{n}\sum |y_i - \hat{y}_i|$. It measures the average absolute magnitude of errors in the original units (minutes).
  • Root Mean Squared Error (RMSE): $\sqrt{\frac{1}{n}\sum (y_i - \hat{y}_i)^2}$. Because errors are squared before averaging, RMSE heavily penalizes large outlier errors.
  • Coefficient of Determination ($R^2$): $1 - \frac{\sum (y_i - \hat{y}_i)^2}{\sum (y_i - \bar{y})^2}$. It measures the proportion of variance explained by the model.
    • I chose MAE as the primary metric because in taxi dispatch, business stakeholders and riders care about the typical expected arrival error in minutes ('on average, our ETA is off by 2.7 minutes'). However, I also track RMSE to ensure the model isn't making catastrophically large errors on outlier trips."
  • Technical Depth:
    • In our holdout evaluation: Candidate MAE is 2.75 min, while RMSE is 4.35 min. RMSE is larger because squaring gives higher weight to rare extreme traffic delays. The baseline Ridge model had an RMSE of 4.81 min.

    • Q28: What is the difference between Data Drift, Concept Drift, and Covariate Shift?

  • Difficulty: Advanced
  • Model Answer:

  • Difficulty: Advanced
  • Model Answer:
    • *"PSI measures the shift between a reference distribution $R$ and a current production distribution $C$. The formula is:* $$\text{PSI} = \sum_{b=1}^{B} \left( P(C_b) - P(R_b) \right) \times \ln\left( \frac{P(C_b)}{P(R_b)} \right)$$ We divide the continuous feature into $B=10$ quantile bins based on the reference dataset. We compute the percentage of samples falling into each bin for both reference ($P(R_b)$) and current ($P(C_b)$). We add a Laplace smoothing epsilon ($1\text{e-}6$) to prevent division by zero. Industry thresholds configured in our platform:
  • $\text{PSI} < 0.10$: Negligible shift (stable distribution).
  • $0.10 \le \text{PSI} < 0.25$: Moderate shift (warning level).
  • $\text{PSI} \ge 0.25$: Significant shift (triggers automated retraining alert)."
  • Technical Depth:
    • Notice that if $P(C_b) > P(R_b)$, both terms $(P(C_b) - P(R_b))$ and $\ln(P(C_b)/P(R_b))$ are positive. If $P(C_b) < P(R_b)$, both terms are negative, so their product is always positive. PSI is symmetric and non-negative.

    • Q30: How does the two-sample Kolmogorov–Smirnov (KS) test work in your drift pipeline?

  • Difficulty: Intermediate
  • Model Answer:
    • *"The Kolmogorov–Smirnov test is a non-parametric statistical hypothesis test that compares two continuous cumulative empirical distributions $F_R(x)$ and $F_C(x)$. The KS statistic $D$ is the maximum vertical distance between the two cumulative distribution functions:* $$D = \sup_{x} |F_R(x) - F_C(x)|$$ In src/mlops_live/monitoring/drift.py, we use scipy.stats.ks_2samp. To declare drift, we check two conditions: 1. Statistical Significance: $p\text{-value} < \alpha$ (where $\alpha = 0.01$). 2. Practical Magnitude: $D > \text{threshold}$ (where threshold is $0.10$). Combining $p$-value with effect size is critical: on large datasets ($n > 10,000$), negligible shifts can have $p < 0.0001$. Requiring $D > 0.10$ prevents false alarms on tiny statistical fluctuations."
  • Technical Depth:
    • For discrete categorical features (like pickup_hour), we evaluate PSI and flag drift if $\text{PSI} \ge 0.25$. For continuous features (like trip_distance), we evaluate both PSI and KS.

    Q49: Live Coding: Write a clean function to calculate Population Stability Index (PSI) in Python.

  • Difficulty: Advanced
  • Model Answer & Code: 
    • import numpy as np


  def calculate_psi(
      reference: np.ndarray,
      current: np.ndarray,
      num_bins: int = 10,
      epsilon: float = 1e-6,
  ) -> float:
      """Calculate Population Stability Index (PSI) between reference and current samples."""
      # 1. Determine quantile bin edges based on reference distribution
      quantiles = np.linspace(0, 100, num_bins + 1)
      bin_edges = np.percentile(reference, quantiles)
      bin_edges[0] -= 1e-5
      bin_edges[-1] += 1e-5

      # 2. Count samples in each bin
      ref_counts, _ = np.histogram(reference, bins=bin_edges)
      cur_counts, _ = np.histogram(current, bins=bin_edges)

      # 3. Calculate proportions with Laplace smoothing epsilon
      ref_pct = (ref_counts + epsilon) / (len(reference) + epsilon * num_bins)
      cur_pct = (cur_counts + epsilon) / (len(current) + epsilon * num_bins)

      # 4. Compute PSI sum
      psi_value = np.sum((cur_pct - ref_pct) * np.log(cur_pct / ref_pct))
      return float(psi_value)
  • Technical Depth:
    • Explain the necessity of epsilon = 1e-6: if a bin has 0 samples in current, cur_pct / ref_pct becomes 0, and np.log(0) yields -inf. Epsilon smoothing ensures numerical stability.
